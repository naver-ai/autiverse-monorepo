# Internationalization (i18n)

Autiverse supports **Korean** and **English** across all layers: mobile app, admin web, and backend.

## Translation Files

Translation files are located at `data/i18n/`:
- `kr.json` — Korean
- `en.json` — English

Both files use a nested key structure organized by feature area:

```json
{
  "Auth": {
    "SignIn": {
      "EnterPasscode": "Enter your passcode"
    }
  },
  "Journaling": {
    "AgentIntro": {
      "FirstVisitGreetingTemplate": "Hello, {child_name}. I'm {agent_name}."
    }
  }
}
```

Use `{variable_name}` syntax for interpolation.

## How Language Switching Works

Language is determined **per Dyad** (child-caregiver pair) through the `dyad.locale` field stored in the database.

```
1. Admin creates Dyad with locale = "Korean" or "English"
   ↓
2. Data stored in database (dyad.locale)
   ↓
3. User signs in → mobile app fetches Dyad profile
   ↓
4. DyadLocaleSync component detects dyad.locale
   ↓
5. Calls i18n.changeLanguage(dyad.locale)
   ↓
6. All UI text updates via react-i18next
   ↓
7. Backend uses dyad.locale to select language-specific AI pipelines
```

### Database Model

The locale is defined in `apps/backend/backend/database/models.py`:

```python
class UserLocale(StrEnum):
    Korean = "Korean"
    English = "English"

class DyadInfo(IdTimestampMixin, WithAvatarConfig):
    locale: UserLocale = Field(
        sa_type=SQLEnum(UserLocale, native_enum=False),
        nullable=False,
        index=True
    )
```

### Frontend (Mobile App)

**Initialization** (`apps/mobile/src/index.js`):

The app initializes i18next with both translation files via the shared library. Default and fallback language is Korean.

```typescript
import { initializeI18n } from '@autiverse-monorepo/ts-core';
initializeI18n(UserLocale.Korean, UserLocale.Korean, {
    middlewares: [initReactI18next]
});
```

**Language Sync** (`apps/mobile/src/app/(app)/_layout.tsx`):

The `DyadLocaleSync` component automatically syncs the i18n language whenever the active Dyad's locale changes:

```typescript
function DyadLocaleSync() {
  const { dyad } = useDyad();
  useEffect(() => {
    if (dyad?.locale && i18n.language !== dyad.locale) {
      i18n.changeLanguage(dyad.locale);
    }
  }, [dyad?.locale]);
  return null;
}
```

### Admin Web

When creating a new Dyad in the admin panel (`apps/admin-web/src/features/dyads/components/NewDyadPanel.tsx`), the locale is a required field (default: Korean).

### Backend

The backend has its own `I18nManager` (`apps/backend/backend/utils/i18n.py`) for server-side translations:

```python
from backend.utils.i18n import t
from backend.database.models import UserLocale

message = t('Home.WriteDiary', UserLocale.English)   # "Write Diary"
message = t('Home.WriteDiary', UserLocale.Korean)     # "일기 쓰기"

# With interpolation
greeting = t('Journaling.AgentIntro.FirstVisitGreetingTemplate',
             UserLocale.English,
             child_name="Alice", agent_name="Buddy")
```

The backend also uses **language-specific AI pipeline classes** for chatbot responses. The appropriate class is selected based on `dyad.locale`:

```python
IntroStageClass = ComicIntroStageEng if dyad.locale == UserLocale.English else ComicIntroStage
```

## Locale-Dependent Behavior

Beyond text translations, locale affects:

- **Text animation speed**: English uses shorter character intervals (60ms vs 100ms for Korean)
- **Date formatting**: Different day name arrays per language
- **Korean grammar**: Josa (particle suffixes) applied only for Korean locale

## Key Files

| File | Role |
|------|------|
| `data/i18n/kr.json` | Korean translations |
| `data/i18n/en.json` | English translations |
| `libs/ts-core/src/lib/i18n.ts` | Shared i18n initialization |
| `apps/mobile/src/app/(app)/_layout.tsx` | `DyadLocaleSync` component |

| `apps/backend/backend/database/models.py` | `UserLocale` enum & `DyadInfo.locale` field |
| `apps/admin-web/src/features/dyads/components/NewDyadPanel.tsx` | Locale selection on Dyad creation |
